# Security Model

Sekai64 treats scene definitions, URLs, and binary assets as untrusted input.

## JSON scenes

- No `eval`, `Function`, executable expressions, or code-bearing JSON
- Plain-object validation and rejection of `__proto__`, `prototype`, and `constructor`
- Maximum 10,000 root objects, hierarchy depth 64, and general nesting depth 96
- Duplicate ID checks and exact failing JSON paths
- Built-in object allowlist plus factories registered explicitly by installed plugins
- Interaction actions resolved through explicit registries only
- Scene patches restricted to supported paths and operations

## Assets

- Protocol allowlist before fetching
- Abort signals, finite retries, bounded concurrency, and custom trusted resolvers
- glTF version, GLB header/chunk boundaries, accessor types, and buffer ranges validated
- Unsupported binary features fail explicitly
- Application code should add content-length and domain policies appropriate to its threat model

## Browser and XR

- Browser navigation actions permit only configured protocols
- DOM text/HTML is not generated by scene data
- WebXR sessions require application user gestures and browser permission behavior
- DOM overlays are passed explicitly by the application
